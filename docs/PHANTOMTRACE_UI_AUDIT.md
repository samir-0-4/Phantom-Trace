# PhantomTrace frontend audit

This pre-implementation audit covers the 15 frontend routes, their shared navigation and controls, and the investigation workflow. The redesign target is a dark forensic intelligence workstation with a restrained cyan accent and a stitch mark that reflects PhantomTrace's Frankenstein theme.

| Surface | Findings | Redesign direction |
| --- | --- | --- |
| Landing and 404 | Oversized gradient sections, decorative chips, animated reveals and several bold security claims distract from the case workflow. Branding differs from the dashboard. | Show how evidence becomes a case, a relationship and a shareable report. Use one wordmark and clear entry and recovery actions. |
| Sign in and registration | Repeated glossy panels, different icon treatments and dense forms. The password visibility control is removed from keyboard navigation. | Use one compact form layout, visible field help and keyboard-operable controls. |
| Dashboard and shell | Greeting, tile stack and always-on AI indicators overshadow recent cases. Some dashboard counts cover the latest 100 cases, while the server total has broader scope. Sidebar navigation can highlight two links on the new-case route. | Put case activity and next actions first, label the scope of counts, and derive navigation state from the current route. |
| Investigations and new case | Loose case rows, crowded titles at narrow widths, unlabeled filters and decorative protocol panels around a short form. Search and category filters apply to the loaded page. | Use labeled filters, resilient list rows and a direct case creation form. Explain the search scope. |
| Case workspace and evidence intake | Case title competes with seven actions. Provenance and relationship between submitted evidence, external checks and interpretation are buried. Long indicators and upload controls need to work at touch widths. | Give case status, evidence and navigation distinct positions. Explain explicit external lookups and keep evidence identifiers legible. |
| Analysis results | Treatments for evidence, agent output and risk are visually similar. Long references compete with severity and progress. | Structure findings by agent and epistemic status, with readable evidence references and a separate risk summary. |
| Evidence graph and campaign | Selected-node details overlay the graph, edges and node types are hard to distinguish, and canvas affordances compete. Campaign cards obscure related cases and shared indicators. | Reserve an inspector region, label relationships, make zoom and fit controls visible, and prioritize related-case and indicator records. |
| Reports and settings | Report index reads like a list of saved documents even when only cases are known. Print styles impede long-section pagination, digest text truncates and live campaign data can blur snapshot scope. Settings hard-code provider and model information. | Create a case report index and a legible print document, distinguish saved and live data, and use accurate read-only settings copy. |
| Shared UI and accessibility | Two overlapping color systems, hard-coded surface shades, low-contrast secondary text, large radii, blur and animated focus cues. Drawer and modal keyboard behavior needs attention. | Use semantic surfaces, readable neutral text, compact controls, visible focus, and narrow-screen and reduced-motion support. Preserve explicit VERIFIED, AI_INFERENCE and UNKNOWN states. |
